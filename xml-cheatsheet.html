XML Basics

XML (eXtensible Markup Language) is a markup language for storing and transporting structured data. It is both human-readable and machine-readable. W3Schools →
Well-formed XML
<?xml version="1.0" encoding="UTF-8"?>
<bookstore xmlns="http://example.com/books">
  <book category="fiction" lang="en">
    <title>The Great Gatsby</title>
    <author>F. Scott Fitzgerald</author>
    <year>1925</year>
    <price>10.99</price>
  </book>
  <book category="science">
    <title>A Brief History of Time</title>
    <author>Stephen Hawking</author>
    <year>1988</year>
    <price>15.99</price>
  </book>
</bookstore>
▶ Well-formed Rules
  • One root element required
  • Case-sensitive: <Tag> ≠ <tag>
  • Every opening tag needs a closing tag (<tag>...</tag> or <tag/>)
  • Attribute values must be in quotes
  • Tags must be properly nested
  • Special chars escaped: &lt; &gt; &amp; &quot;
The prolog declares the XML version and encoding before the root element.
Prolog & Declaration
<?xml version="1.0" encoding="UTF-8"?>
<?xml version="1.0" encoding="UTF-8" standalone="yes"?>

<!-- Attributes: -->
  version   — XML version (always "1.0" or "1.1")
  encoding  — Character encoding (UTF-8, ISO-8859-1, ...)
  standalone — "yes" if no external DTD referenced
▶ Notes
  • Prolog is optional but recommended
  • standalone="yes" means no external DTD
  • Default encoding is UTF-8
Namespaces prevent element name conflicts by using a URI prefix.
Namespaces
<!-- Default namespace (applies to all children) -->
<root xmlns="http://example.com/ns">
  <child/>  <!-- inherits namespace -->
</root>

<!-- Prefixed namespace -->
<root xmlns:h="http://www.w3.org/TR/html4/"
       xmlns:f="http://www.example.com/furniture">
  <h:table>
    <h:tr><h:td>HTML table</h:td></h:tr>
  </h:table>
  <f:table>
    <f:name>Coffee Table</f:name>
  </f:table>
</root>
▶ Namespace Rules
  • xmlns:prefix="URI" declares a namespace
  • xmlns="URI" sets default (no prefix)
  • URI is a unique identifier, not fetched
  • Prefixes prevent name collisions

DTD (Document Type Definition)

DTD defines the structure and rules of an XML document. It specifies allowed elements, attributes, and nesting. W3Schools →
Internal DTD
<?xml version="1.0"?>
<!DOCTYPE root [
  <!ELEMENT root (child+) >
  <!ELEMENT child (#PCDATA) >
]>
<root>
  <child>Hello World</child>
</root>
▶ Internal DTD

Defined inside the XML file within <!DOCTYPE> brackets.

Pros: Single file, no external dependency.
Cons: Repeated across documents, not reusable.

External DTDs are stored in a separate .dtd file and referenced from the XML.
External DTD
teams.dtd:
<!ELEMENT teams (team+) >
<!ELEMENT team (name, salary) >
<!ELEMENT name (#PCDATA) >
<!ELEMENT salary (#PCDATA) >
<!ATTLIST team aid ID #REQUIRED>

teams.xml:
<?xml version="1.0"?>
<!DOCTYPE teams SYSTEM "teams.dtd">
<teams>
  <team aid="t1">
    <name>Arun</name>
    <salary>50000</salary>
  </team>
</teams>
▶ External DTD

SYSTEM — private DTD (local file or URL)
PUBLIC — public DTD (registered identifier)

Pros: Reusable, single source of truth.
Cons: Extra file to maintain.

DTD syntax overview with all declaration types and symbols.
DTD Syntax Reference
<!-- Element declarations -->
<!ELEMENT name (content-model) >

<!-- Attribute declarations -->
<!ATTLIST element
  attr-name  type    default
  attr-name2 type    default>

<!-- Entity declarations -->
<!ENTITY logo "SYSTEM logo.png">

<!-- Notation declarations -->
<!NOTATION pdf SYSTEM "Acrobat">
▶ DTD Symbols
+1 or more
*0 or more
?0 or 1
|OR (choice)
,AND (sequence)
()Grouping
#PCDATAParsed character data
EMPTYNo content allowed
ANYAny content allowed

DTD Element Declarations

The <!ELEMENT> declaration defines what content an element can contain: text, child elements, or both. W3Schools →
Content Models
<!-- Text only -->
<!ELEMENT title (#PCDATA) >
<!ELEMENT price (#PCDATA) >

<!-- Child elements (sequence) -->
<!ELEMENT book (title, author, year) >

<!-- Child elements (choice) -->
<!ELEMENT choice (option1 | option2 | option3) >

<!-- Mixed content -->
<!ELEMENT para (#PCDATA | b | i)* >

<!-- Empty element -->
<!ELEMENT br EMPTY >

<!-- Any content -->
<!ELEMENT wildcard ANY >
▶ Content Types
#PCDATAText content (parsed)
EMPTYNo children/text
ANYAny content allowed
(a, b)Sequence: a then b
(a | b)Choice: a or b
Occurrence indicators control how many times an element may appear.
Occurrence Indicators
<!-- + : one or more -->
<!ELEMENT teams (team+) >

<!-- * : zero or more -->
<!ELEMENT list (item*) >

<!-- ? : zero or one -->
<!ELEMENT book (title, author, year?) >

<!-- No indicator : exactly one -->
<!ELEMENT person (name, age) >

<!-- Mixed with occurrence -->
<!ELEMENT para (#PCDATA | b | i)+ >
▶ Quick Reference
(a)exactly 1
(a+)1 or more
(a*)0 or more
(a?)0 or 1 (optional)

Tip: Occurrence indicators can only appear on groups () or single elements.

DTD Attribute Declarations

<!ATTLIST> declares attributes for an element, including type and default value. W3Schools →
ATTLIST Declaration
<!ATTLIST element-name
  attr-name1  type  default-value
  attr-name2  type  default-value>

<!-- Example -->
<!ATTLIST book
  id         ID          #REQUIRED
  lang       CDATA       #IMPLIED
  edition    CDATA       "1"
  format     (paper|ebook) #FIXED "paper">
▶ Default Values
#REQUIREDMust be present
#IMPLIEDOptional
#FIXED "val"Fixed value, cannot change
"default"Default if omitted
Attribute types define what values are allowed: strings, unique IDs, references, or enumerated choices.
Attribute Types
<!-- CDATA — character data (string) -->
<!ATTLIST img src CDATA #REQUIRED>

<!-- ID — unique identifier -->
<!ATTLIST person pid ID #REQUIRED>

<!-- IDREF — reference to an ID -->
<!ATTLIST ref personRef IDREF #REQUIRED>

<!-- IDREFS — space-separated list of IDREFs -->
<!ATTLIST group members IDREFS #REQUIRED>

<!-- Enumerated — choice from list -->
<!ATTLIST text align (left|center|right) "left">

<!-- NMTOKEN — valid XML name token -->
<!ATTLIST item code NMTOKEN #REQUIRED>

<!-- NMTOKENS — space-separated NMTOKENs -->
<!ATTLIST tag tokens NMTOKENS #IMPLIED>

<!-- ENTITY — parsed entity reference -->
<!ATTLIST doc logo ENTITY #IMPLIED>

<!-- NOTATION — reference to notation -->
<!ATTLIST file type NOTATION (pdf|gif) #REQUIRED>
▶ Type Summary
CDATAString (no entities)
IDUnique ID (XML name)
IDREFReferences an ID
IDREFSMultiple IDREFs
NMTOKENName token
ENTITYParsed entity ref
(a|b|c)Enumerated choice

XSD Schema

XML Schema (XSD) provides richer validation than DTD: data types, namespaces, inheritance, and fine-grained constraints. W3Schools →
Schema: Simple & Complex Types
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">

  <!-- Simple Type — restriction on base type -->
  <xs:simpleType name="salaryType">
    <xs:restriction base="xs:decimal">
      <xs:minInclusive value="0"/>
      <xs:maxInclusive value="999999"/>
    </xs:restriction>
  </xs:simpleType>

  <!-- Complex Type — elements + attributes -->
  <xs:complexType name="teamType">
    <xs:sequence>
      <xs:element name="name"   type="xs:string"/>
      <xs:element name="salary" type="salaryType"/>
    </xs:sequence>
    <xs:attribute name="aid" type="xs:ID" use="required"/>
  </xs:complexType>

  <!-- Root Element -->
  <xs:element name="teams">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="team" type="teamType"
                    maxOccurs="unbounded"/>
      </xs:sequence>
    </xs:complexType>
  </xs:element>

</xs:schema>
▶ Occurrence Attributes
minOccursMin times (default 1)
maxOccursMax times (default 1)
unboundedNo upper limit

Sequence: Ordered children.
Choice: Only one child allowed.
All: Any order, each once.

A side-by-side comparison of DTD and XML Schema capabilities.
DTD vs Schema
| Feature        | DTD                 | Schema (XSD)              |
|----------------|---------------------|---------------------------|
| Syntax         | Custom               | XML-based                |
| Data Types     | Limited (#PCDATA)    | Rich (string, int, date)  |
| Namespaces     | No                   | Full support               |
| Inheritance    | No                   | Complex type extension    |
| Validation     | Structure only       | Structure + Content       |
| Constraints    | Basic (occurrence)   | min/max, patterns, facets |
| Self-describing| No                   | Yes (XML format)          |
| Editor support | Limited              | Widely supported          |
▶ When to Use
  • DTD: Simple docs, legacy systems, DTD-based configs
  • Schema: Data validation, typed content, modern apps
  • Schema is the standard for new projects

Common DTD configs: web.xml, struts-config.xml
Common Schema configs: pom.xml, hibernate.cfg.xml

XML Parsing

Three main XML parsing APIs: DOM (tree), SAX (event), and StAX (streaming pull). W3Schools →
DOM vs SAX vs StAX
| Feature    | DOM                | SAX                | StAX              |
|------------|--------------------|--------------------|-------------------|
| Approach   | Tree (load all)    | Event-driven        | Pull (cursor)     |
| Memory     | High (entire tree)  | Low (streaming)     | Low (streaming)   |
| Speed      | Fast reads         | Fast parse          | Fast parse        |
| Navigation | Random access      | Forward only        | Forward only      |
| Best for   | Small docs, R/W    | Large docs, read    | Large docs, R/W   |
| Modify     | Yes                 | No                  | No                |
▶ When to Use
  • DOM: Need to navigate/edit the whole tree
  • SAX: Read-only, very large files, low memory
  • StAX: Best balance — streaming + in control
Java DOM parser reads the entire XML into a Document tree for random access.
Java DOM Parser
import javax.xml.parsers.*;
import org.w3c.dom.*;
import java.io.*;

DocumentBuilderFactory factory = DocumentBuilderFactory.newInstance();
DocumentBuilder builder = factory.newDocumentBuilder();
Document doc = builder.parse(new File("teams.xml"));

Element root = doc.getDocumentElement();
NodeList teams = root.getElementsByTagName("team");

for (int i = 0; i < teams.getLength(); i++) {
  Element team = (Element) teams.item(i);
  String aid  = team.getAttribute("aid");
  String name = team.getElementsByTagName("name")
                  .item(0).getTextContent();
  String sal  = team.getElementsByTagName("salary")
                  .item(0).getTextContent();
  System.out.println("Team: " + name + " ($" + sal + ")");
}
▶ Output
Team: Arun ($50000)
XPath is a query language for selecting nodes from an XML document.
XPath Expressions
<!-- XPath syntax -->
/root/child             → absolute path
//child                 → any child anywhere
//team[@aid='t1']       → team with aid="t1"
//team[salary > 30000]  → team with salary > 30000
//team/name             → all name elements in team
/teams/team[1]          → first team child
/teams/team[last()]     → last team child
/teams/team[position()<3] → first 2 teams
//name/text()           → text content of name

<!-- Java XPath usage -->
XPathFactory xf = XPathFactory.newInstance();
XPath xpath = xf.newXPath();
String expr = "//team[@aid='t1']/name";
NodeList result = (NodeList) xpath.evaluate(
    expr, doc, XPathConstants.NODESET);
▶ XPath Functions
text()Node text content
@attrAttribute value
last()Last position
position()Current index
count()Node count
contains()String match
normalize-space()Trim whitespace
