Variables

A variable is a named box that holds a value you can read and change later. Docs →
variables.js
// a variable is a named box
let score = 10;
score = 25;  // the value can change
score = 42;
▶ animation
score
10 25 42

Why it matters: naming a value once lets you reuse it and update it everywhere from a single place.

Gotcha: const can't be reassigned, and using a variable before it's declared is an error.

Data Types

Every value has a type that decides what it holds and what you can do with it. Docs →
types.js
let n   = 42;        // int
let pi  = 3.14;      // float
let s   = "hi";      // string
let ok  = true;      // boolean
let xs  = [1, 2, 3]; // list
let obj = { a: 1 };  // object
▶ animation
int42
float3.14
string"hi"
booleantrue
list[1,2,3]
object{a:1}

Why it matters: the type decides which operations are valid, so knowing it prevents surprising results.

Gotcha: "5" + 1 is "51" (a string), not 6 — JS joins text instead of adding.

Operators

Operators combine values: arithmetic produces a number, comparison produces a boolean. Docs →
operators.js
let sum = 3 + 4;    // 7
let big = 5 > 2;    // true
let eq  = 5 === 5;  // true
▶ animation
3+4= 7
5 > 2 → true 2 > 5 → false

Why it matters: operators are how you compute and compare — the core of every expression.

Gotcha: prefer === over ==; == converts types, so 0 == "" is surprisingly true.

Conditionals (if / else)

A condition picks one branch to run — the if branch when true, otherwise else. Docs →
conditional.js
if (age >= 18) {
  status = "adult";
} else {
  status = "minor";
}
▶ animation

Why it matters: branching lets a program react differently to different data.

Gotcha: if (x = 5) assigns instead of comparing — you meant if (x === 5).

Loops (for / while)

A loop repeats the same block of code a set number of times. Docs →
loop.js
// runs 3 times
for (let i = 0; i < 3; i++) {
  console.log(i); // 0, 1, 2
}
▶ animation
0
1
2
i goes 0 → 1 → 2, then repeats

Why it matters: loops do repetitive work without copy-pasting the same lines.

Gotcha: forget to advance the counter and the condition never becomes false — an infinite loop.

Functions

A function is a reusable machine: give it an input, it runs, and it hands back an output. Docs →
function.js
function double(x) {
  return x * 2;
}
double(5); // 10
▶ animation
5
→
double()
→
10

Why it matters: functions package logic under a name so you can reuse and test it in isolation.

Gotcha: a function with no return hands back undefined.

Parameters & Return

Arguments flow in through parameters; the return value flows back out to the caller. Docs →
params.js
function greet(name) {   // parameter
  return "Hi " + name; // return value
}
greet("Sam"); // "Hi Sam"
▶ animation
arg in →
greet(name)
→ value out
"Sam"
"Hi Sam"

Why it matters: parameters make a function flexible; the return value is how it reports its result.

Gotcha: return exits the function immediately — any code after it never runs.

Scope

A global variable is visible everywhere; a local one lives only inside its function. Docs →
scope.js
let g = "global";   // visible everywhere
function f() {
  let local = "local"; // only inside f()
  return local;
}
// local is not visible out here
▶ animation
global scope
g = "global"
f() local scope
local = "local"

Why it matters: scope keeps local names from clashing or leaking across the whole program.

Gotcha: a variable declared inside a function can't be read from outside it.

Static vs Instance Methods

A static method is called on the class itself; an instance method is called on an object made from it. Docs →
methods.js
class Cat {
  static species() { return "feline"; } // on the class
  speak() { return "meow"; }            // on an object
}
Cat.species();      // class-level
new Cat().speak();  // instance-level
▶ animation
static
Cat.species()
called on the class
instance
cat.speak()
called on an object

Why it matters: statics belong to the class as a whole; instance methods act on one object's own data.

Gotcha: calling an instance method on the class (Cat.speak()) fails — you need an object first.

Recursion

A recursive function calls itself; frames stack up until a base case, then unwind returning values. Docs →
recursion.js
function fact(n) {
  if (n === 1) return 1;   // base case
  return n * fact(n - 1);  // calls itself
}
fact(3); // 6
▶ animation
fact(3)→ 6
fact(2)→ 2
fact(1)→ 1
frames stack up, then unwind

Why it matters: recursion expresses problems that naturally break into smaller copies of themselves.

Gotcha: a missing or wrong base case recurses forever and overflows the call stack.

Arrays / Collections

An array stores many values in order, each reachable by its index; you can add to it and iterate over it. Docs →
arrays.js
let fruits = ["apple", "banana", "orange"];
fruits.push("grape"); // add
fruits[0];              // "apple" (index 0)
for (const f of fruits) { } // iterate
▶ animation

🍌

🍊

🍇

Why it matters: arrays hold ordered, indexable groups of values you can loop over.

Gotcha: indexes start at 0, so the last item is arr[length - 1], not arr[length].

Nested Loops

A loop inside another loop: the inner loop runs fully for every single step of the outer loop. Docs →
nested-loops.js
// outer runs 3 times
for (let i = 0; i < 3; i++) {
  // inner runs fully each time
  for (let j = 0; j < 3; j++) {
    cell(i, j);  // 3 × 3 = 9 steps
  }
}
▶ animation
0,0
0,1
0,2
1,0
1,1
1,2
2,0
2,1
2,2
inner j loops fully for each outer i · O(n × n)

Why it matters: nested loops walk every combination — grids, tables, pairs of items.

Gotcha: work grows as n × n, so a large n gets slow fast (that's O(n²)).

The Call Stack

Each call pushes a frame on top of the stack; when it returns, its frame is popped off (last in, first out). Docs →
call-stack.js
function a() { b(); }
function b() { c(); }
function c() { return 1; }
a(); // a → b → c, then unwind
▶ animation
a()
b()
c()
push on call ↑   pop on return ↓   (LIFO)

Why it matters: the stack is how a program tracks which call is running and where to return next.

Gotcha: calls that nest too deep (often runaway recursion) overflow the stack.

Value vs Reference

Copying a primitive copies the value into a new box; copying an object copies a reference to the same box. Docs →
value-reference.js
let a = 5, b = a; // copy the value
b = 9;           // a is still 5

let x = [1,2,3], y = x; // copy the reference
y.push(4);              // x sees it too
▶ animation
primitive — copies the value
a = 5
b = 59
two separate boxes — change b, a stays 5
reference — copies the pointer
one box, two names — change via x, y sees it

Why it matters: it decides whether a copy is independent or quietly shares the same data.

Gotcha: copying an object copies the reference, so edits through one name show up on both.

Mutability

A mutable value can be changed in place; an immutable one can't, so "changing" it really makes a new value. Docs →
mutability.js
let arr = [1, 2, 3];
arr.push(4);  // same array → [1,2,3,4]

let s = "cat";
s = s + "s";  // "cats" — a NEW string
▶ animation
mutable — change in place
arr = [1,2,3][1,2,3,4]
push(4) — the same array changes
immutable — a new value
"cat"
→
"cats"
reassign — a brand-new string is made

Why it matters: knowing what can change in place helps you avoid accidental shared-data bugs.

Gotcha: two variables pointing at one mutable object both see every change.

Scope & Closures

A closure is a function that remembers variables from the scope where it was created, even after that scope returns. Docs →
closures.js
function makeCounter() {
  let count = 0;        // private
  return () => ++count; // remembers count
}
const next = makeCounter();
next(); next(); next(); // 1, 2, 3
▶ animation
makeCounter() — returned
closure keeps count = 0123
the returned function remembers & bumps its own count

Why it matters: closures let a function keep private state that survives after the outer call ends.

Gotcha: a closure captures the variable, not a snapshot — the classic var-in-a-loop trap.

Date & Time

The Unix epoch is the number of seconds since 1970-01-01 UTC — one plain number you convert to and from a date. Docs →
date-time.js
// epoch = seconds since 1970-01-01 UTC
const e = Math.floor(Date.now() / 1000); // date → epoch
const d = new Date(e * 1000);            // epoch → date (ms!)
▶ animation
epoch 1700000000
seconds since 1970-01-01 UTC, ticking up
⇕
date Tue, 14 Nov 2023 22:13:20 GMT
epoch → date: new Date(e*1000)  ·  date → epoch: Math.floor(Date.now()/1000)

Why it matters: epoch seconds are a single, timezone-free number that's easy to store and compare.

Gotcha: JS Date uses milliseconds, not seconds — multiply epoch seconds by 1000.
