How an AI app connects

An AI agent reaches real tools and data by connecting through an MCP server: it sends a request and gets a response back. Docs →

The agent never touches the tool directly. It asks the MCP server, the server runs the tool, and the result flows back — one request, one response.

request (agent → tool) response (tool → agent)
Think — the model plans its next step.
Act — it calls a tool through MCP (search, read a file, query a DB).
Observe — it reads the result, then loops again until the goal is met.

The whole AI workflow in one picture

How the pieces fit: a prompt goes into the LLM, the agent loop thinks → acts → observes using skills / tools and MCP servers, memory / RAG feeds context back in, and the answer returns to you. Follow the moving dot. Docs →

1You type a prompt — a question or a task. It is sent to the model as plain text.

2The LLM splits it into tokens. Everything it can see must fit in its context window; temperature sets how random its wording is; its parameters / weights are what it learned in training.

3Think — run as an agent, the model plans the next step instead of answering straight away.

4Act — it calls a skill / tool directly, e.g. web_search.

5Observe — the result goes back into the context, and the loop continues.

6Think again — it still needs live data, so this time it reaches for an MCP server.

7MCP: the client (inside the app) sends the request, the server runs the tool or reads the data, and the result travels back the same way.

8Observe → store: tool results and documents are kept in memory (often as embeddings).

9RAG: retrieve the most relevant pieces and augment the context the LLM reads.

10With everything in context, the LLM writes the final answer — and it flows back to you.

prompt · tokens LLM agent loop skills · tools · MCP memory · RAG final answer

One sentence: an agent is an LLM in a loop; skills / tools are the functions it may call; MCP is the standard plug that connects it to those tools and data; memory / RAG keeps the right context in front of the model; the LLM does the thinking and writes the answer.

MCP (Model Context Protocol)

MCP is an open standard that lets an AI app connect to outside tools and data through small programs called servers — like a USB-C port for AI. Docs →
In motion · one client, many servers

One client, many servers: each server wraps one tool or data source. The client sends a request, the server runs the tool, and the response flows back — one at a time. Add a server to the config and the agent gains that ability.

Client vs Server
# ── Two roles in MCP ──

MCP Client:   Lives inside the AI app (the agent).
             Discovers tools and calls them.
             Examples: Claude Desktop, an IDE, your code.

MCP Server:   A small program that exposes capabilities.
             Wraps a tool, API, database, or files.
             Examples: filesystem, GitHub, Postgres.

# ── The flow ──
# client  ──request──▶  server  ──runs──▶  tool/data
# client  ◀─response──  server  ◀─result─  tool/data

# One client can connect to many servers at once.
▶ Who does what
Client — asks for tools & calls them (the agent side)
Server — provides the tools (the data side)
Transport — stdio (local) or HTTP (remote)
Think of a server as a universal adapter: write it once, any MCP client can use it.
How to connect — mcpServers config (JSON)
// A client reads this config, then launches each server.
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/Users/me/projects"
      ]
    }
  }
}
▶ What happens next
1. The client starts the filesystem server.
2. It asks the server: "what tools do you have?"
3. The agent can now call those tools (read/list files).
client connects → tools appear → agent uses them
Add more servers under mcpServers to grant more abilities.

AI Agents

An AI agent is an LLM that runs in a loop: it thinks about the goal, acts by calling a tool, observes the result, and repeats until it is done. Docs →
In motion · the loop finishes a goal

Each lap of the loop finishes one step of the goal: think what to do next, act by calling a tool, observe the result. When the goal is met, the agent stops looping and answers.

The think → act → observe loop (pseudo-code)
# ── A minimal agent loop ──
history = [goal]

while not done:
    # THINK — the model plans using the goal + history
    thought = model.think(history)

    if thought.wants_tool:
        # ACT — call a tool (often through an MCP server)
        result = tools.run(thought.tool, thought.args)

        # OBSERVE — feed the result back in
        history.append(result)
    else:
        # model decided it has the final answer
        answer = thought.text
        done = True
▶ The loop, in words
Think — decide the next step toward the goal
Act — call a tool (search, read, write, query)
Observe — read the result and learn from it
Repeat until the goal is met. The tools usually come from MCP servers.
Tools: the agent's hands
# ── A tool is a function the model may call ──
# The model is given each tool's name, description,
# and the shape of its inputs. It chooses when to use one.

Typical tools:
  search_web(query)        # look something up
  read_file(path)          # inspect a file
  run_sql(query)           # query a database
  send_email(to, body)     # take an action

# With MCP, you don't hand-write these — a server
# advertises its tools and the agent discovers them.
▶ Why tools matter
An LLM alone can only produce text.
Tools let it read fresh data and change the world.
MCP is how tools get plugged in without custom glue code.
LLM + tools (via MCP) = agent

Machine Learning Fundamentals

Machine Learning (ML) is a subset of AI that provides machines the ability to learn automatically and improve from experience without being explicitly programmed. Core building blocks: Algorithms, Models, Features, and Data. W3Schools →
In motion · learning = fitting a line

Learning = adjusting a model’s parameters so its predictions miss the data by a little less each step. Watch the line swing toward the points as the loss falls; once fitted, it can predict unseen values. Supervised, unsupervised and reinforcement learning differ only in what counts as “error”.

Linear Algebra for ML

Algebra is the language of science, engineering, and economics. Linear Algebra focuses on linear equations and matrices — the data structures powering every ML algorithm. NumPy is the standard library. W3Schools →
In motion · the dot product

A vector is an arrow with length and direction; a matrix is a grid of them. The dot product a·b measures how much two vectors point the same way (the amber shadow is b projected onto a): positive = similar, zero = unrelated, negative = opposite. That single number is the heart of neurons, SVMs and embedding similarity.

Probability in Machine Learning

Probability theory underpins all of ML — from Bayes' theorem in classifiers to cross-entropy loss in neural networks. Models are fundamentally probability distributions. W3Schools →
In motion · from samples to a distribution

A random variable takes values by chance. Collect enough samples and a distribution appears; its expected value E[X] is the centre and σ the spread. Models are distributions as well: a classifier outputs P(label | features), and an LLM outputs P(next token | previous tokens).

Random Variables
# ── Random Variable ──
# A variable whose values are numerical outcomes
# of a random phenomenon

# Example: Coin toss
# X = 1 for Heads, X = 0 for Tails

# ── Discrete Random Variable ──
# Countable values (gaps between them)
Example: Number of bedrooms (1, 2, 3...)
ML use: Classification → discrete categories

# ── Continuous Random Variable ──
# Any value within a range (no gaps)
Example: Exact price of a house, weight
ML use: Regression → continuous outputs

# ── Loss Functions Differ ──
Continuous:  MSE (Mean Squared Error)
Discrete:    Cross-Entropy Loss

Expected Value & Variance
# ── Expected Value E[X] ──
# Long-run average of repetitions
# Represents the "center" of a distribution

# Example: rolling a die
E_die = (1+2+3+4+5+6) / 6   # = 3.5

# Cost Function = expected value (average) of errors
# MSE = average squared difference over dataset

# ── Variance σ² ──
# How spread out numbers are from the mean
# High variance = widely scattered
# Low variance = clustered near mean

# ── Standard Deviation σ ──
# √variance — back to original units

# ── ML Applications ──
SGD:  high variance in updates → loss wiggles
Mini-batch:  reduces variance → smoother convergence
Xavier Init:  maintains consistent variance across layers
Feature Scaling: normalizes variance → easier optimization

SGD: high variance updates → noisy loss curve
Mini-batch: reduces variance, smoother convergence

Conditional Probability
# ── Core Formula ──
# P(A|B) = P(A∩B) / P(B)
# "Shrinking the world" — filter by known event B

# ── Intersection vs. Conditional ──
# P(A∩B): global scope (entire universe)
# P(A|B): filtered scope (only where B is true)

# ── Example: Bug Rate ──
# Total files = 100 (universe)
# Junior files = 20 (condition B)
# Buggy junior files = 5 (intersection A∩B)

p_A_inter_B = 5.0 / 100.0   # 0.05 (global bug rate)

# Condition B applied — scope reduced
p_A_given_B = 5.0 / 20.0    # 0.25 (junior bug rate)

# ── More Conditions → More Precision ──
# P(A | B ∩ C ∩ D)
# Denominator shrinks → more specific, smaller sample
# ML: Personalized predictions
# P(Buy | User=JavaDev ∩ City=Mumbai ∩ Time=Night)
▶ ML Applications
P(A|B) = P(A∩B) / P(B)
Classification: P(label | features)
LLMs: P(next_token | all_previous_tokens)
Agents: P(success | action ∩ environment)
Naive Bayes: uses conditional probability to predict categories
Cross-Entropy: measures difference between actual & predicted distributions
Addition & Multiplication Rules
# ── Addition Rule ──
# P(A ∪ B) = P(A) + P(B) − P(A∩B)
# Probability that A OR B occurs

# Mutually exclusive: P(A∪B) = P(A) + P(B)
# Example: rolling 2 or 4 on a die = 1/6 + 1/6 = 1/3

# ML: Multi-class classification
# Sum of probabilities for all classes = 1 (Softmax)

# ── Multiplication Rule ──
# P(A∩B) = P(A) × P(B|A)
# Probability that A AND B both occur

# Independent: P(A∩B) = P(A) × P(B)

# ── Chain Rule (4-Stage) ──
# P(A∩B∩C∩D) = P(A) · P(B|A) · P(C|A∩B) · P(D|A∩B∩C)

# Example: "Perfect Trade"
# P(Bullish)           = 0.60
# P(Rate Cut | Bullish) = 0.30
# P(Rise | Both)        = 0.80
# P(ITM | All)          = 0.90
# Total: 0.6 × 0.3 × 0.8 × 0.9 = 12.96%

# ── Backpropagation Connection ──
# Chain Rule in calculus (gradient flow):
# dy/dx = dy/du · du/dx
# Multiply local gradients moving backward
# Repeated multiplication → Vanishing Gradients
▶ Practical Use
Addition: P(A∪B) = P(A)+P(B)−P(A∩B)
Multiply: P(A∩B) = P(A)·P(B|A)
Multi-class: Softmax ensures Σ = 1
Backprop: chain rule = multiplication of gradients
Vanishing: 0.25 × 0.25 × ... → 0 (stops learning)
Sequence Prediction: LLMs predict next word using multiplication rule, one word at a time
Bayes' Theorem
# ── Bayes' Theorem ──
# P(A|B) = P(B|A) × P(A) / P(B)
# "Given evidence B, update belief about A"

# ── Spam Detection Example ──
P_spam      = 0.3     # prior: 30% of emails are spam
P_word      = 0.05    # "free" in 5% of all emails
P_word_spam = 0.8     # "free" in 80% of spam

# P(Spam | word="free")
P_spam_given = (P_word_spam * P_spam) / P_word
# = (0.8 × 0.3) / 0.05 = 4.8 → clamped to ~0.96

# ── Naive Bayes ──
# Applies Bayes' theorem for each feature
# Assumes feature independence
from sklearn.naive_bayes import GaussianNB
clf = GaussianNB()
clf.fit(X_train, y_train)
pred = clf.predict(X_test)
▶ Bayes Breakdown
P(A|B) = P(B|A)·P(A) / P(B)
P(A) — prior (initial belief)
P(B|A) — likelihood (evidence given A)
P(B) — marginal (total evidence)
P(A|B) — posterior (updated belief)
Spam: "free" → 96% chance spam
Naive Bayes: classifier using feature independence
Cross-Entropy Loss
import numpy as np

# ── Cross-Entropy ──
# -Σ y_true × log(y_pred)
# Measures distance between true & predicted distributions

# ── Binary Cross-Entropy (binary classification) ──
def bce_loss(y_true, y_pred):
    eps = 1e-7  # avoid log(0)
    return -np.mean(
        y_true * np.log(y_pred + eps) +
        (1 - y_true) * np.log(1 - y_pred + eps)
    )

# ── Categorical Cross-Entropy (multi-class) ──
def cce_loss(y_true, y_pred):
    return -np.sum(y_true * np.log(y_pred + 1e-7))

# ── PyTorch Built-in ──
import torch.nn as nn
loss_fn = nn.CrossEntropyLoss()
loss = loss_fn(logits, labels)

# Used in Word2Vec training

Vectors & Embeddings

Word vectors map discrete tokens into continuous geometric space where distance = similarity. The Distributional Hypothesis: "You shall know a word by the company it keeps." Semantic understanding in AI is an emergent property of geometric alignment. W3Schools →
In motion · how embeddings learn meaning

Embeddings start random. Training pulls words that share contexts together and pushes unrelated ones apart. After millions of tiny nudges, distance = similarity: cat and dog sit together, apple lands far away — and directions like “gender” become consistent arrows.

The Fundamental Problem
# ── Symbol vs. Meaning ──
# "cat" is an arbitrary signifier
# Computer sees ASCII: 01100011 01100001 01110100
# "dog" → 01100100 01101111 01100111
# No mathematical overlap in bit patterns

# ── Distributional Hypothesis (1950s) ──
# J.R. Firth: "You shall know a word by the
#             company it keeps."
#
# "cat" appears near: purr, meow, fur, claw, pet
# "dog" appears near: bark, fur, claw, pet
# → Shared context overlap = semantic similarity
#
# "apple" appears near: eat, pie, tree, juice
# → Negligible overlap with "cat"

# Convert "meaning" → "probability"
# High co-occurrence probability → close vectors
▶ The Goal
Move from discrete (isolated symbols) to continuous (vector space)
On the map: distance = similarity

One-Hot Encoding (Why It Fails)
# ── Vocabulary V ──
V = ["cat", "dog", "apple", "king",
     "queen", "ate", "chased"]
|V| = 7

# One-hot: vector of length |V|, single '1'
cat  = [1,0,0,0,0,0,0]
dog  = [0,1,0,0,0,0,0]
apple= [0,0,1,0,0,0,0]

# ── Orthogonality Problem ──
# Dot product of any two one-hot vectors = 0
# Sim(cat, dog) = 0
# Sim(cat, apple) = 0
# → Semantically blind! Every word is equally dissimilar
# → Geometric distance between any two = √2

# For 50K vocab: one sentence of 10 words
# = 500,000 values, 499,990 are zeros
# → Computationally intractable for deep learning

# ── Solution: Dense Embeddings ──
# Compress: 50,000 sparse → 300 or 1024 dense floats
▶ One-Hot vs Dense
One-Hot: all pairs have sim = 0
cat · dog = 0 (orthogonal)
Dense: meaningful similarity
cat · dog ≈ 0.999 (close)
Dimensions encode semantic features: animacy, action, food/object
Cosine Similarity
import numpy as np

def cosine_sim(a, b):
    return np.dot(a, b) / (
        np.linalg.norm(a) * np.linalg.norm(b)
    )

# One-hot: all pairs = 0
cat_oh = np.array([1,0,0,0])
dog_oh = np.array([0,1,0,0])
cosine_sim(cat_oh, dog_oh)   # 0.0 — semantically blind

# Dense embeddings — meaningful similarity
cat_vec  = np.array([0.95, 0.88, -0.90])
dog_vec  = np.array([0.92, 0.85, -0.85])
apple_vec= np.array([-0.95,-0.80, 0.98])

cosine_sim(cat_vec, dog_vec)     # ~0.999 (similar!)
cosine_sim(cat_vec, apple_vec)   # ~-0.97  (opposite)
▶ Vector Arithmetic
V(King) − V(Man) + V(Woman) ≈ V(Queen)
"Gender" is a measurable vector offset applied consistently across gendered word pairs.
Not hard-coded — a mathematical inevitability of training forces.
Training: Initialization & Pull
# ── Step 1: Random Initialization ──
# Tabula Rasa — model starts ignorant
# Random normal distribution (μ=0, σ=1.0)

Word   Dim1(x)  Dim2(y)  Dim3(z)
Cat      0.20    -0.50     0.80
Dog     -0.90     0.10    -0.20
Apple    0.25    -0.45     0.75
King     0.05     0.90    -0.10

# Paradox: cat near apple (dist ≈ 0.086)
#          cat far from dog  (dist ≈ 1.60)
# Training must fix this!

# ── Skip-Gram Task ──
# Given target word → predict context words
# Input → Hidden (embedding) → Output (softmax)

# ── The "Pull" (Positive Sampling) ──
# Training pair: Target="dog", Context="chased"
v_dog    = [-0.90,  0.10, -0.20]
u_chased = [ 0.10, -0.30,  0.40]

# Dot product = similarity score
score = (-0.90*0.10) + (0.10*-0.30) + (-0.20*0.40)
# = -0.09 - 0.03 - 0.08 = -0.20

# Sigmoid → probability
# σ(x) = 1 / (1 + e⁻ˣ)
P = 1 / (1 + np.exp(0.20))   # ≈ 0.45

# Target = 1.0 (they ARE neighbors)
error = 0.45 - 1.0   # = -0.55

# Gradient descent update (η = 0.1)
adj = -error * u_chased * 0.1
# = 0.055 × [0.10, -0.30, 0.40]
# = [0.0055, -0.0165, 0.022]

new_dog = v_dog + adj
# = [-0.8945, 0.0835, -0.178]
# Dog shifted slightly toward Chased
▶ Why "Cat" Follows "Dog"
Shared context effect:
"The cat chased the mouse" → cat pulled toward "chased"
"The dog chased the cat" → dog pulled toward "chased"
Both pulled toward same point → they converge!
Even though "The dog is a cat" never appears, shared neighbor "chased" acts as gravitational anchor.
"Apple" left behind: pulled toward "ate" not "chased" → separate cluster with "pear", "banana", "pie"
Negative Sampling (The "Push")
# ── Problem: Mode Collapse ──
# Without negative sampling, all vectors could
# converge to same point (dot product → max)
# Error → 0 by claiming everything is synonym

# ── Solution: Negative Sampling ──
# For each positive pair (Dog/Chased),
# randomly select k words that are NOT the context

# Negative samples for "Dog": "King", "Apple"
# Goal:
#   Dog + Chased → P → 1.0 (Pull)
#   Dog + King   → P → 0.0 (Push)
#   Dog + Apple  → P → 0.0 (Push)

# ── Negative Update Math ──
v_dog   = [-0.89,  0.08, -0.17]
v_apple = [ 0.25, -0.45,  0.75]

score = (-0.89*0.25)+(0.08*-0.45)+(-0.17*0.75)
# = -0.22 - 0.036 - 0.1275 = -0.38

P = 1 / (1 + np.exp(0.38))   # ≈ 0.40
error = 0.40 - 0.0            # = +0.40 (positive → push!)

# Push: subtract Apple from Dog
new_dog = v_dog - (error * v_apple * 0.1)
# Increases distance between them
▶ Training Dynamics
Pull: shared contexts (chased, pet, fur) = springs pulling cat & dog together
Push: negative sampling = magnets pushing cat away from apple, king, tree
Over millions of iterations → vectors settle into Low Energy State
1. Random init — all words random
2. Pull — shared contexts attract
3. Push — negative sampling repels
4. Converge — semantic clusters form
Final Vectors & Emergent Properties

Bitness — 32-bit vs 64-bit

Bitness defines a CPU's address width — how many bits it uses to reference memory. 1 Address = 1 Byte (byte-addressable memory). Bit-depth defines address length, not data size.
In motion · each bit doubles the range

Every extra bit doubles how many values fit: 8 bits give 256, 64 bits give 18.4 quintillion. A CPU’s bitness is the width of a memory address: 32-bit can point at 4 GB, 64-bit at far more than any machine holds — it says nothing about how many cores it has.

The Bit Progression (Powers of 2)
# Doubling bits → exponentially increases range: 2ⁿ

8-bit:   0–255
         ASCII chars, RGB colors (8 bits each)
         # Basic unit of data

16-bit:  0–65,535
         # Legacy systems, early games

32-bit:  0–4,294,967,295 (≈ 4.29 billion)
         Main CPUs (1990–2010)
         India's Vikram 32-bit space chip
         # Legacy standard

64-bit:  0–18,446,744,073,709,551,615 (≈ 18.4 quintillion)
         Current CPUs (Dhruv64)
         Enables huge RAM addressing
         # Modern standard

128/256-bit:  Specialized use
         AES-256 encryption
         SIMD vector processing
         # NOT for general CPU addressing (pointer bloat)
         Combinations ≈ 1.15 × 10⁷⁷
▶ Bit Progression
8-bit: 0–255 (ASCII, RGB)
16-bit: 0–65,535
32-bit: 0–4.29B (legacy CPUs)
64-bit: 0–18.4 quintillion
256-bit: used in AES encryption
RAM Addressing (32-bit vs 64-bit)
# Memory is byte-addressable — every byte has a unique address

# ── 32-bit: 2³² addresses ──
2^32 = 4,294,967,296 bytes ≈ 4 GB max RAM
# 32-bit architectures → 4 GB ceiling

# ── 64-bit: 2⁶⁴ addresses ──
2^64 = 18,446,744,073,709,551,616 bytes ≈ 16 EB
# Practically: 256 TB – 4 PB (48–57 address lines)

# ── 2025 Real-World Limit ──
# Modern CPUs use 48–57 address lines
Min: 256 TB    Max: 4 PB physical RAM

# ── Two's Complement for -1 ──
# All bits = 1
8-bit:  11111111 = -1 (also 255 unsigned)
64-bit: 1111...1111 = -1 (64 ones)
# Adding 1 to -1 overflows to 0 — perfect for CPU arithmetic

# ── Addressing vs Processing ──
# A 64-bit CPU handles 64-bit integers,
# NOT 64 cores
