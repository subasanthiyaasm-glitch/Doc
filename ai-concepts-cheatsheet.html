Machine Learning Fundamentals

Machine Learning (ML) is a subset of AI that provides machines the ability to learn automatically and improve from experience without being explicitly programmed. Core building blocks: Algorithms, Models, Features, and Data. W3Schools →
Key Concepts & Vocabulary
# ── Core ML Terminology ──

Algorithms:       Rules & statistical techniques to learn patterns from data
Model:            Trained by an ML algorithm on data
Predictor Variable: Feature of data used to predict the output
Response Variable:  Output variable predicted from the predictor
Training Data:     Data used to build the model
Testing Data:      Data used to evaluate the model

# ── ML Problem Types ──
Every ML problem falls into one of three categories:

1. Regression     — predict continuous values
2. Classification — predict discrete labels
3. Clustering     — group similar data points

Three Types of Learning
# ── Supervised Learning ──
Trained on labeled data (input → known output)
Regression:     predict continuous value (price, temp)
Classification:  predict discrete label (spam / not spam)
Algorithms:     Linear Regression, Logistic Regression,
                 SVM, KNN, Decision Tree, Random Forest,
                 Naïve Bayes

# ── Unsupervised Learning ──
Trained on unlabeled data — discovers hidden patterns
Clustering:     group similar data points (K-Means, C-Means)
Association:     find co-occurring rules (Apriori)
# No guidance — algorithm finds structure on its own

# ── Reinforcement Learning ──
An agent interacts with an environment,
produces actions, and discovers rewards.
State → Action → Reward → Next State
Algorithms:     Q-Learning, SARSA
Used in: game AI, robotics, autonomous driving

Evaluation Metrics
# ── Classification Metrics ──

# Accuracy = correct / total predictions
accuracy = (TP + TN) / (TP + TN + FP + FN)

# Precision = TP / (TP + FP)
# "Of all predicted positive, how many are correct?"

# Recall = TP / (TP + FN)
# "Of all actual positive, how many did we catch?"

# F1 Score = 2 × (Precision × Recall) / (Precision + Recall)
# Harmonic mean — balances precision & recall

# ── Regression Metrics ──

# MSE = mean((actual − predicted)²)
# Mean Squared Error — penalizes large errors

# R² = variance explained by the model
# 1.0 = perfect, 0.0 = no better than mean

Expected Value & Variance
# ── Expected Value E[X] ──
# Long-run average of repetitions
# Represents the "center" of a distribution

# Example: rolling a die
E_die = (1+2+3+4+5+6) / 6   # = 3.5

# Cost Function = expected value (average) of errors
# MSE = average squared difference over dataset

# ── Variance σ² ──
# How spread out numbers are from the mean
# High variance = widely scattered
# Low variance = clustered near mean

# ── Standard Deviation σ ──
# √variance — back to original units

# ── ML Applications ──
SGD:  high variance in updates → loss wiggles
Mini-batch:  reduces variance → smoother convergence
Xavier Init:  maintains consistent variance across layers
Feature Scaling: normalizes variance → easier optimization
▶ Optimization Impact
E[X] = long-run average = center of distribution
Var(X) = spread from mean (σ²)
σ = std deviation (same units as data)
SGD: high variance updates → noisy loss curve
Mini-batch: reduces variance, smoother convergence
Xavier Init: keeps activation variance stable across layers
Feature Scaling: transforms loss landscape from narrow valley → symmetric bowl
Conditional Probability
# ── Core Formula ──
# P(A|B) = P(A∩B) / P(B)
# "Shrinking the world" — filter by known event B

# ── Intersection vs. Conditional ──
# P(A∩B): global scope (entire universe)
# P(A|B): filtered scope (only where B is true)

# ── Example: Bug Rate ──
# Total files = 100 (universe)
# Junior files = 20 (condition B)
# Buggy junior files = 5 (intersection A∩B)

p_A_inter_B = 5.0 / 100.0   # 0.05 (global bug rate)

# Condition B applied — scope reduced
p_A_given_B = 5.0 / 20.0    # 0.25 (junior bug rate)

# ── More Conditions → More Precision ──
# P(A | B ∩ C ∩ D)
# Denominator shrinks → more specific, smaller sample
# ML: Personalized predictions
# P(Buy | User=JavaDev ∩ City=Mumbai ∩ Time=Night)
▶ ML Applications
P(A|B) = P(A∩B) / P(B)
Classification: P(label | features)
LLMs: P(next_token | all_previous_tokens)
Agents: P(success | action ∩ environment)
Naive Bayes: uses conditional probability to predict categories
Cross-Entropy: measures difference between actual & predicted distributions
Addition & Multiplication Rules
# ── Addition Rule ──
# P(A ∪ B) = P(A) + P(B) − P(A∩B)
# Probability that A OR B occurs

# Mutually exclusive: P(A∪B) = P(A) + P(B)
# Example: rolling 2 or 4 on a die = 1/6 + 1/6 = 1/3

# ML: Multi-class classification
# Sum of probabilities for all classes = 1 (Softmax)

# ── Multiplication Rule ──
# P(A∩B) = P(A) × P(B|A)
# Probability that A AND B both occur

# Independent: P(A∩B) = P(A) × P(B)

# ── Chain Rule (4-Stage) ──
# P(A∩B∩C∩D) = P(A) · P(B|A) · P(C|A∩B) · P(D|A∩B∩C)

# Example: "Perfect Trade"
# P(Bullish)           = 0.60
# P(Rate Cut | Bullish) = 0.30
# P(Rise | Both)        = 0.80
# P(ITM | All)          = 0.90
# Total: 0.6 × 0.3 × 0.8 × 0.9 = 12.96%

# ── Backpropagation Connection ──
# Chain Rule in calculus (gradient flow):
# dy/dx = dy/du · du/dx
# Multiply local gradients moving backward
# Repeated multiplication → Vanishing Gradients
▶ Practical Use
Addition: P(A∪B) = P(A)+P(B)−P(A∩B)
Multiply: P(A∩B) = P(A)·P(B|A)
Multi-class: Softmax ensures Σ = 1
Backprop: chain rule = multiplication of gradients
Vanishing: 0.25 × 0.25 × ... → 0 (stops learning)
Sequence Prediction: LLMs predict next word using multiplication rule, one word at a time
Bayes' Theorem
# ── Bayes' Theorem ──
# P(A|B) = P(B|A) × P(A) / P(B)
# "Given evidence B, update belief about A"

# ── Spam Detection Example ──
P_spam      = 0.3     # prior: 30% of emails are spam
P_word      = 0.05    # "free" in 5% of all emails
P_word_spam = 0.8     # "free" in 80% of spam

# P(Spam | word="free")
P_spam_given = (P_word_spam * P_spam) / P_word
# = (0.8 × 0.3) / 0.05 = 4.8 → clamped to ~0.96

# ── Naive Bayes ──
# Applies Bayes' theorem for each feature
# Assumes feature independence
from sklearn.naive_bayes import GaussianNB
clf = GaussianNB()
clf.fit(X_train, y_train)
pred = clf.predict(X_test)
▶ Bayes Breakdown
P(A|B) = P(B|A)·P(A) / P(B)
P(A) — prior (initial belief)
P(B|A) — likelihood (evidence given A)
P(B) — marginal (total evidence)
P(A|B) — posterior (updated belief)
Spam: "free" → 96% chance spam
Naive Bayes: classifier using feature independence
Cross-Entropy Loss
import numpy as np

# ── Cross-Entropy ──
# -Σ y_true × log(y_pred)
# Measures distance between true & predicted distributions

# ── Binary Cross-Entropy (binary classification) ──
def bce_loss(y_true, y_pred):
    eps = 1e-7  # avoid log(0)
    return -np.mean(
        y_true * np.log(y_pred + eps) +
        (1 - y_true) * np.log(1 - y_pred + eps)
    )

# ── Categorical Cross-Entropy (multi-class) ──
def cce_loss(y_true, y_pred):
    return -np.sum(y_true * np.log(y_pred + 1e-7))

# ── PyTorch Built-in ──
import torch.nn as nn
loss_fn = nn.CrossEntropyLoss()
loss = loss_fn(logits, labels)

Vectors & Embeddings

Word vectors map discrete tokens into continuous geometric space where distance = similarity. The Distributional Hypothesis: "You shall know a word by the company it keeps." Semantic understanding in AI is an emergent property of geometric alignment. W3Schools →
The Fundamental Problem
# ── Symbol vs. Meaning ──
# "cat" is an arbitrary signifier
# Computer sees ASCII: 01100011 01100001 01110100
# "dog" → 01100100 01101111 01100111
# No mathematical overlap in bit patterns

# ── Distributional Hypothesis (1950s) ──
# J.R. Firth: "You shall know a word by the
#             company it keeps."
#
# "cat" appears near: purr, meow, fur, claw, pet
# "dog" appears near: bark, fur, claw, pet
# → Shared context overlap = semantic similarity
#
# "apple" appears near: eat, pie, tree, juice
# → Negligible overlap with "cat"

# Convert "meaning" → "probability"
# High co-occurrence probability → close vectors
▶ The Goal
Move from discrete (isolated symbols) to continuous (vector space)
On the map: distance = similarity
"cat" close to "dog" → machine deduces shared attributes
cat → [0.95, 0.88, −0.90]
dog → [0.92, 0.85, −0.85]
apple → [−0.95, −0.80, 0.98]
One-Hot Encoding (Why It Fails)
# ── Vocabulary V ──
V = ["cat", "dog", "apple", "king",
     "queen", "ate", "chased"]
|V| = 7

# One-hot: vector of length |V|, single '1'
cat  = [1,0,0,0,0,0,0]
dog  = [0,1,0,0,0,0,0]
apple= [0,0,1,0,0,0,0]

# ── Orthogonality Problem ──
# Dot product of any two one-hot vectors = 0
# Sim(cat, dog) = 0
# Sim(cat, apple) = 0
# → Semantically blind! Every word is equally dissimilar
# → Geometric distance between any two = √2

# For 50K vocab: one sentence of 10 words
# = 500,000 values, 499,990 are zeros
# → Computationally intractable for deep learning

# ── Solution: Dense Embeddings ──
# Compress: 50,000 sparse → 300 or 1024 dense floats
▶ One-Hot vs Dense
One-Hot: all pairs have sim = 0
cat · dog = 0 (orthogonal)
Dense: meaningful similarity
cat · dog ≈ 0.999 (close)
Dimensions encode semantic features: animacy, action, food/object
Cosine Similarity
import numpy as np

def cosine_sim(a, b):
    return np.dot(a, b) / (
        np.linalg.norm(a) * np.linalg.norm(b)
    )

# One-hot: all pairs = 0
cat_oh = np.array([1,0,0,0])
dog_oh = np.array([0,1,0,0])
cosine_sim(cat_oh, dog_oh)   # 0.0 — semantically blind

# Dense embeddings — meaningful similarity
cat_vec  = np.array([0.95, 0.88, -0.90])
dog_vec  = np.array([0.92, 0.85, -0.85])
apple_vec= np.array([-0.95,-0.80, 0.98])

cosine_sim(cat_vec, dog_vec)     # ~0.999 (similar!)
cosine_sim(cat_vec, apple_vec)   # ~-0.97  (opposite)
▶ Vector Arithmetic
V(King) − V(Man) + V(Woman) ≈ V(Queen)
"Gender" is a measurable vector offset applied consistently across gendered word pairs.
Not hard-coded — a mathematical inevitability of training forces.
Training: Initialization & Pull
# ── Step 1: Random Initialization ──
# Tabula Rasa — model starts ignorant
# Random normal distribution (μ=0, σ=1.0)

Word   Dim1(x)  Dim2(y)  Dim3(z)
Cat      0.20    -0.50     0.80
Dog     -0.90     0.10    -0.20
Apple    0.25    -0.45     0.75
King     0.05     0.90    -0.10

# Paradox: cat near apple (dist ≈ 0.086)
#          cat far from dog  (dist ≈ 1.60)
# Training must fix this!

# ── Skip-Gram Task ──
# Given target word → predict context words
# Input → Hidden (embedding) → Output (softmax)

# ── The "Pull" (Positive Sampling) ──
# Training pair: Target="dog", Context="chased"
v_dog    = [-0.90,  0.10, -0.20]
u_chased = [ 0.10, -0.30,  0.40]

# Dot product = similarity score
score = (-0.90*0.10) + (0.10*-0.30) + (-0.20*0.40)
# = -0.09 - 0.03 - 0.08 = -0.20

# Sigmoid → probability
# σ(x) = 1 / (1 + e⁻ˣ)
P = 1 / (1 + np.exp(0.20))   # ≈ 0.45

# Target = 1.0 (they ARE neighbors)
error = 0.45 - 1.0   # = -0.55

# Gradient descent update (η = 0.1)
adj = -error * u_chased * 0.1
# = 0.055 × [0.10, -0.30, 0.40]
# = [0.0055, -0.0165, 0.022]

new_dog = v_dog + adj
# = [-0.8945, 0.0835, -0.178]
# Dog shifted slightly toward Chased
▶ Why "Cat" Follows "Dog"
Shared context effect:
"The cat chased the mouse" → cat pulled toward "chased"
"The dog chased the cat" → dog pulled toward "chased"
Both pulled toward same point → they converge!
Even though "The dog is a cat" never appears, shared neighbor "chased" acts as gravitational anchor.
"Apple" left behind: pulled toward "ate" not "chased" → separate cluster with "pear", "banana", "pie"
Negative Sampling (The "Push")
# ── Problem: Mode Collapse ──
# Without negative sampling, all vectors could
# converge to same point (dot product → max)
# Error → 0 by claiming everything is synonym

# ── Solution: Negative Sampling ──
# For each positive pair (Dog/Chased),
# randomly select k words that are NOT the context

# Negative samples for "Dog": "King", "Apple"
# Goal:
#   Dog + Chased → P → 1.0 (Pull)
#   Dog + King   → P → 0.0 (Push)
#   Dog + Apple  → P → 0.0 (Push)

# ── Negative Update Math ──
v_dog   = [-0.89,  0.08, -0.17]
v_apple = [ 0.25, -0.45,  0.75]

score = (-0.89*0.25)+(0.08*-0.45)+(-0.17*0.75)
# = -0.22 - 0.036 - 0.1275 = -0.38

P = 1 / (1 + np.exp(0.38))   # ≈ 0.40
error = 0.40 - 0.0            # = +0.40 (positive → push!)

# Push: subtract Apple from Dog
new_dog = v_dog - (error * v_apple * 0.1)
# Increases distance between them
▶ Training Dynamics
Pull: shared contexts (chased, pet, fur) = springs pulling cat & dog together
Push: negative sampling = magnets pushing cat away from apple, king, tree
Over millions of iterations → vectors settle into Low Energy State
1. Random init — all words random
2. Pull — shared contexts attract
3. Push — negative sampling repels
4. Converge — semantic clusters form
Final Vectors & Emergent Properties
# ── After Training (Converged State) ──
Word   Dim1(Living)  Dim2(Active)  Dim3(Food)
Cat      0.95          0.88         -0.90
Dog      0.92          0.85         -0.85
Apple   -0.95         -0.80          0.98
King     0.96         -0.50         -0.60

# Cat vs Dog (Animal cluster):
# Both high in Dim1 (Living), Dim2 (Active)
# Both negative in Dim3 (Not Food)
# → cosine similarity ≈ 1.0

# Cat vs Apple (Semantic gap):
# Cat: Living (0.95), Not Food (-0.90)
# Apple: Non-Living (-0.95), Food (0.98)

# King: Living (0.96) but not Pet (-0.50)

# Architecture: Input → Hidden → Output
# Hidden layer = the embedding vector
# Training: predict context from target (Skip-Gram)
# Negative Sampling: push non-neighbors apart
# Result: similar words cluster in vector space
# Limitation: "bank" has one vector regardless of context

# "bank" in "river bank" vs "bank account"

# Input = word_vector + positional_encoding

# "The bank of money"     → bank → Finance

1. Random init — all words at random points
2. Pull — shared contexts attract vectors
3. Push — negative sampling repels non-neighbors
4. Converge — semantic clusters form
cat & dog → animal cluster
apple → food cluster (far away)
Word2Vec: static (one vector per word)
Transformer: contextual (vector changes per sentence)

Bitness — 32-bit vs 64-bit

Bitness defines a CPU's address width — how many bits it uses to reference memory. 1 Address = 1 Byte (byte-addressable memory). Bit-depth defines address length, not data size.
The Bit Progression (Powers of 2)
# Doubling bits → exponentially increases range: 2ⁿ

8-bit:   0–255
         ASCII chars, RGB colors (8 bits each)
         # Basic unit of data

16-bit:  0–65,535
         # Legacy systems, early games

32-bit:  0–4,294,967,295 (≈ 4.29 billion)
         Main CPUs (1990–2010)
         India's Vikram 32-bit space chip
         # Legacy standard

64-bit:  0–18,446,744,073,709,551,615 (≈ 18.4 quintillion)
         Current CPUs (Dhruv64)
         Enables huge RAM addressing
         # Modern standard

128/256-bit:  Specialized use
         AES-256 encryption
         SIMD vector processing
         # NOT for general CPU addressing (pointer bloat)
         Combinations ≈ 1.15 × 10⁷⁷
▶ Bit Progression
8-bit: 0–255 (ASCII, RGB)
16-bit: 0–65,535
32-bit: 0–4.29B (legacy CPUs)
64-bit: 0–18.4 quintillion
256-bit: used in AES encryption
RAM Addressing (32-bit vs 64-bit)
# Memory is byte-addressable — every byte has a unique address

# ── 32-bit: 2³² addresses ──
2^32 = 4,294,967,296 bytes ≈ 4 GB max RAM
# 32-bit architectures → 4 GB ceiling

# ── 64-bit: 2⁶⁴ addresses ──
2^64 = 18,446,744,073,709,551,616 bytes ≈ 16 EB
# Practically: 256 TB – 4 PB (48–57 address lines)

# ── 2025 Real-World Limit ──
# Modern CPUs use 48–57 address lines
Min: 256 TB    Max: 4 PB physical RAM

# ── Two's Complement for -1 ──
# All bits = 1
8-bit:  11111111 = -1 (also 255 unsigned)
64-bit: 1111...1111 = -1 (64 ones)
# Adding 1 to -1 overflows to 0 — perfect for CPU arithmetic

# ── Addressing vs Processing ──
# A 64-bit CPU handles 64-bit integers,
# NOT 64 cores
